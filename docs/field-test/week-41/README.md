## 测试 A：采购单 → 采购员（约 5 分钟，微信即可完成）

**怎么做**：把两个 `.txt` 文件的全文**原样**粘进微信发给采购员（不要提前解释格式），然后问三个问题：

1. 「这两段文字你能**直接转发**给菜贩吗？如果不能，差在哪一步？」
2. 「缺什么字段你才敢下单？」（重点听：要不要联系方式、送货时间、规格/品牌备注、单价单位"每包"是否歧义——鸡蛋"180 个"菜贩听得懂是"一箱"吗？）
3. 「'预估 ¥1339.50（按上次价）'这句会惹麻烦吗？要保留还是删掉？」

**通过标准**：采购员回答"直接能转"或"只缺一两个字段"。如果要求加字段，逐条记进反馈表——每条都是 schema 缺口的候选。

## 测试 B：备料单 → 乌克兰帮厨（约 10 分钟，打印）

**怎么做**：把 `prep-list-uk.md` 打印出来（A4，字号尽量大），交给帮厨，同样**不做口头讲解**，问：

1. 「看得懂吗？明天照这张单子备料，你缺什么信息？」
2. 指着 `(без специфікації нарізки)` 那一行（鸡蛋）问：「这个提示对你有用吗，还是噪音？」
3. 指着番茄行的切法（Шматки рулонним нарізанням, 3–4 cm）问：「'滚刀块'这个翻譯你能照着切吗？需要图吗？」
4. 「数量单位（кг / шт / г / л）都顺手吗？」

**通过标准**：帮厨能复述出"10 月 5 日午餐要 30 кг 番茄切滚刀块"这个级别的信息。切法译名看不懂 → 记录原话，回投 techniques.json 词表修订。
