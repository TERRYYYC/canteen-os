# ADR-0010: 限制知识库原始来源的读取

## Context

ADR-0009 第 3 项允许厨师、采购和管理员读取整个 `/knowledge/*` 网关。抖音菜谱导入后，这个范围过宽：菜谱明细与历史版本包含来源原文、视频证据和媒体元数据，菜谱列表的封面字段也可能带未公开的外链地址。独立审查在本机复现了采购令牌读取来源正文。采购人员完成本次购买所需的是已发布的菜单、备料与采购资料，不依赖知识库原始证据。

## Decision

本决策取代 ADR-0009 第 3 项中关于知识库菜谱读取角色的部分，其他 SQLite 和写入决定保持不变。
ADR-0009 把固定菜谱写入 Git 记为下一阶段；基础 PR #120 已实现该路径，本决策同时约束其公开投影。

- `/knowledge/recipes*` 的列表、明细、历史、旧版证据和来源参考图，仅厨师、管理员令牌可读。拒绝采购令牌的请求在接触知识库服务前返回 403。
- `/knowledge/favorites*` 与 `/knowledge/assets/:id/content` 继续仅厨师、管理员可用。知识库健康状态、标准食材和技法查询仍按原有读角色开放。
- 采购和帮厨使用已发布且按版本固定的菜单、备料与采购投影；未核权的原片图与来源正文不从这些投影补出。
- 完整来源图或视频今后若要向帮厨开放，需先确认使用权、目标角色和具体发布路径，再另行修改权限与投影。

## Consequences

- 采购令牌不能再打开知识库菜谱管理页；这与其现行工作流程一致，但若以后需要采购角色查阅菜谱，应设计只包含所需字段的单独只读视图。
- 权限矩阵与回归测试需覆盖列表、当前明细、历史、旧版证据和图片二进制。知识库本体仍只绑定本机回环地址，角色鉴权由 CanteenOS 网关执行。
- 食材和技法查询仍沿用原读角色，但返回的资料可能带既有 Git 导入的 `legacy.original` 与图片元数据；不能把该接口描述为仅含名称的纯字典。若这些旧字段未来含非公开内容，应另设采购专用投影并收紧权限。
- 本 ADR 记录的是 `0.3.0-alpha.3` 分支的隔离验证决策；真实候选审核、素材使用权和公网发布另行验收。
