# ADR-0009: SQLite 菜谱知识库与 CanteenOS 管理入口

## 背景

此前 Git JSON 适合少量、随发布固定的厨房资料，但每日收集和编辑大量菜谱需要查询、事务、关系与可追溯历史。用户明确要求 SQL 管理，并选择先独立运行知识库、再接回 CanteenOS。同名菜（例如多款红烧肉）是独立记录，不强制归并为一条主菜谱。

本 ADR 补充 ADR-0007/0008；不改写旧决定或旧发布记录。日常知识库写入策略由用户的新要求替代原有无数据库限制。

## 决定

1. SQLite 是新知识库的日常写入真源，远程应用与数据库文件在同一主机。事务同步写入当前资料、不可变历史快照与幂等回执。每份菜谱采用独立 UUID，更新采用版本条件写入。
2. 菜谱保存多语名称、说明、所有配料和调料、数量原文、步骤、来源、图片与视频引用。缺失数量/份数保持缺失；长十进制用字符串。原始来源与已有演示/未核验标签保留。
3. 既有 CanteenOS 鉴权后端新增受控 `/knowledge/*` 网关。读权限沿用厨师、采购、管理员；写权限仅厨师和管理员。上游服务地址由部署配置决定，浏览器不传地址；旧令牌不传给上游。
4. CanteenOS 新增独立加载的菜谱知识库页面，用于列表、查询、创建、修改及版本历史。日常编辑不需要生成 Git commit 或重新发布静态站。
5. 导入保留旧命名空间/实体 ID 与新 UUID 映射，原始文件、源 Git 版本、内容 hash 作为证据归档。同一来源快照重放不产生重复记录，也不重复增加版本。新的源版本不得静默覆盖已编辑资料。
6. 本轮菜单、备料、采购继续使用原有固定 Git 发布资料。下一阶段通过显式选择 `recipeId + version` 导出完整依赖快照，再产生真实发布 commit。不能将 UUID 或 SQLite 版本冒充 Git SHA，也不能让旧菜单随知识库修改漂移。

2026-10-04 隐私收紧：第 3 项的通用读权限不再适用于 `/knowledge/recipes*`。列表可带未公开封面地址，明细与历史可带来源原文和媒体元数据，因此整组菜谱接口只允许厨师、管理员令牌；采购角色继续读取已发布的菜单、备料和采购数据。来源图片二进制及收藏候选接口同样限厨师、管理员。

## 后果

- 可独立增长菜谱库、保存多款同名菜，保留数据来源并逐步补全资料。
- 管理页面依赖知识库服务；故障必须明确显示，不能悄悄回退另一写入库。
- 当前远程原型仍采用 SSH 隧道和旧 CanteenOS 角色令牌。SQLite 本身不开放网络端口。
- 旧编辑器表示已发布/待发布的历史资料，知识库与其不自动双向同步；页面须说明入口区别。
- 文件型媒体和 SQLite 一起备份；应用升级必须保留数据 Git heads、授权配置、数据库及可回滚的旧构建。

## 本轮验收

远程实际旧快照完整导入、重复导入幂等；在 CanteenOS 页面可读取和编辑同一 SQLite 菜谱；保存生成新版本且历史可查；权限和冲突正确；旧菜单/备料/采购的固定版本未变化；服务重启仍可读取。
