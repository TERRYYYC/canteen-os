> 本文回答四个问题：设计有没有偏离目标；现在能不能开始出品；第一轮做到什么算完；之后每一轮怎么走。它取代 `architecture.md` §6 和 `project-summary.md` §8 的旧路线图。
>

## 0. 目标（不变）

**让一个中国师傅带着本地乌克兰帮厨，在海外稳定做出中餐，并且买对料。**

一个知识库，每天三张单：备料单（帮厨）、采购单（采购员）、菜单（顾客）。视频是知识库的输入通道。三语是前提。允许不完整。

"稳定做出中餐"这句话的度量在厨房里，不在 CI 里。这是本文所有判断的依据。

---

## 1. 偏移分析：方向没偏，重心偏了

逐个组件对照目标：

| 组件 | 服务谁 | 现状 | 判断 |
|---|---|---|---|
| 5 实体 `data/` + schema | 全部 | 稳定，ADR-0006 定案 | 对齐 |
| `expand()` + 采购单渲染 | 采购员 | 有黄金测试、微信文本已能出 | 对齐，完成度最高 |
| 备料单渲染 | **帮厨（目标的主角）** | 只有文字：数量 + 技法名 + 备注；**无图片、无时间、无分工** | 对齐，**完成度最低** |
| 菜单渲染 | 顾客 | 有 | 对齐，优先级最低 |
| readiness 关卡 | 编辑者 | 有 | 对齐 |
| techniques.json | 帮厨 | 中文骨架有；en/uk 机翻未做；无配图 | 半完成 |
| 食材库 | 全部 | 5 个，手填；Wikidata 脚本就绪未跑；调料缺位（G1） | 薄 |
| 翻译工作流 | 帮厨 | 设计有（场景 H），**未落地**；现有 uk 是 agent 手打 | 未开始 |
| 视频 skill | 输入通道 | 契约验证过；自动化未验证 | 领先于依赖 |
| PWA | 展示层 | 未开始 | 可后置 |
| 评分 / 报告 / 小程序 / 多租户 | — | 推迟 | 正确 |

三个重心偏移：

**1. 工程严谨度集中在采购员那张单上，目标的主角（帮厨）拿到的是最薄的东西。** 你在第三轮说得很清楚：帮厨要知道切成什么样、准备哪些、图片和步骤都重要。现在备料单没有图。采购单有黄金测试锁数字，备料单连一张示意图都没有。

**2. 依然零接触现实。** 6 个 commit、约 30 份文档、21 个测试，没有一个乌克兰帮厨看过备料单，没有一个采购员收到过采购单。"任何 agent 都能接手"是仓库的状态，不是产品的状态。

**3. 输入通道跑在依赖前面。** 视频 skill 的输出要匹配食材库和技法闭集，而食材库只有 5 个、调料为零。视频再自动化，出来的也是一堆"匹配不到、转复核"。正确顺序是：食材库 → 词表 → 翻译 → 视频。

一个隐藏成本没人提：**视频给的是 2 人份，知识库要的是 50 份标准化配方，中间那步是师傅拿秤量出来的。** 每道菜约 30 分钟，10 道菜就是师傅半天。这是第一轮真正的人力成本，比任何代码都贵。

## 2. 现在能不能开始出品：能。第一轮的"品"是三张单的界面，没有人当路由器

条件已经具备：目标清楚、数据模型定案、引擎能跑、两张单能出真东西、契约在真视频上验过、调研足够。

**第一轮的产品形态：一个只读 PWA，三个页面，推送数据即上线。** 原则是链路上不能有人手工搬运：数据进仓库 → 自动构建 → 每个人打开自己的页面。

```
data/ 改动 push
  → CI：schema 校验 → 缺失的 en/uk 自动机翻（术语表 + lock 文件，人工改过的不覆盖）
  → 构建：引擎在构建期 expand 全部菜单计划，产出三张单的静态页面 + 图片
  → 部署：静态托管（GitHub Pages / Cloudflare Pages），PWA 离线缓存
帮厨   打开 /prep     → 今天的备料单（uk）
采购员 打开 /purchase → 本周采购单，一键复制微信文本
顾客   打开 /menu     → 今天的菜单（三语）
```

三个页面的内容：

| 页面 | 给谁 | 必须有 | 不做 |
|---|---|---|---|
| `/prep` | 帮厨 | 按日期、按菜品；每个配料一行：食材照片、切法照片、数量、技法名（uk）、备注；步骤带视频片段；大字、离线可用；语言切换 | 勾选完成、分工指派 |
| `/purchase` | 采购员 | 按供应商分组、包数、预估价；"复制为微信文本"；每行可展开"为什么是这个数"（trace） | 状态流转、收货 |
| `/menu` | 顾客 | 菜品照片、三语名、过敏原、当天供应 | 点餐、评分 |

第一轮里唯一的人工环节是**录入**：Terry 改 JSON、师傅口头给份数。录入是作者，不是路由器；第二轮把它也交给界面（见 §4）。

开工前的四件小事和一个前提：

| 开工前必须 | 工作量 |
|---|---|
| 修 margin 不乘 pcs 的错误（引擎 + 测试 + ADR-0006 §3） | 1 小时 |
| G2：`qty.unit` 允许 `to-taste`，采购侧跳过、备料单保留 | 1 小时 |
| G1：调料库先手填 20 个最常用的（生抽/老抽/蚝油/料酒/糖/淀粉/白醋/胡椒……） | 2 小时 |
| dish/ingredient schema 加图片字段的落盘约定（`data/dishes/<id>/images/`）和 prep 的"提前多久" | 半天 |
| **前提：一个真实厨房**——一位师傅、一位帮厨、一位采购员、一周真实菜单 | 要确认 |

技术边界（避免第一轮膨胀）：无后端、无登录、无数据库；引擎在构建期跑，浏览器只渲染；一个 Vite 项目放 `packages/web/`；设计 token 自持，不绑 web-only 组件库，为后续小程序留路。

第一轮的设计工作：三个页面的版式，重点是 `/prep` 的一行（食材照片 | 切法照片 | 数量 | 技法 | 备注）在手机竖屏上怎么排。

## 3. 第一轮完成标准：一个真实的星期

第一轮结束 = 以下全部满足，缺一不算：

**数据**
- 真实菜单里的 ≥ 10 道菜入库（不是只有番茄炒蛋），每道达到"能教"关卡：有切配的配料都有 prep 规格和一张图。
- 食材 ≥ 60 个，含调料；这 10 道菜的技法词表无空引用。
- 所有 uk 文本至少被一个母语者看过一遍（帮厨本人算）。

**真实使用**
- 帮厨用手机打开 `/prep` 连续 5 个工作日，没有人给他发过截图或纸。记录每天"看不懂/找不到"的条目数：阻塞性为 0，非阻塞性每天 < 3。
- 采购员从 `/purchase` 自己复制微信文本发给菜贩连续 1 周，没有人替他生成过。记录每种食材的多买/少买：**因缺料做不出的菜 = 0**；生鲜多买 < 20%。
- `/menu` 给顾客看过一次（可选，不阻塞结束）。
- 厨房断网时 `/prep` 仍能打开上一次的内容。

**过程**
- 新增一道菜（从视频或手工）到"能教"状态并出现在帮厨手机上，Terry 的时间 < 1 小时，翻译零手工。
- 从 push 到三个页面更新，无人工步骤。
- 测试周内 schema 冻结，不改。
- 测试周内每一次"不对"都记录下来，周末汇总成第二轮的输入。

**明确不在第一轮**：任何写入界面（份数录入、勾选、编辑）、登录、后端、真实 API 视频自动化、Wikidata 全量拉取（按需拉 60 个即可）、评分、报告。

## 4. 之后每一轮怎么走

每轮形状一样：**一个新输出或一个新输入通道 + 一项新数据能力 + 在厨房用满一周 + 退出标准在厨房里量**。下一轮的触发条件来自厨房，不来自路线图。

| 轮 | 名字 | 触发条件（厨房里发生了什么） | 做什么 | 退出标准 |
|---|---|---|---|---|
| 1 | 三张单上屏 | 有一个真实厨房 | 只读 PWA 三页面 + 自动构建部署 + 自动翻译，见 §2 §3 | 见 §3 |
| 2 | 写入上屏 | 师傅口头报份数、Terry 改 JSON 成为每周的固定摩擦；或帮厨想勾"做完了" | 界面写入：师傅在 `/plan` 填份数和排菜、帮厨勾选完成、采购员改包数——写回仓库（GitHub API / git-CMS 模式，仍无自建后端）；Terry 退出日常链路 | 连续 2 周 Terry 没碰过 JSON |
| 3 | 输入自动化 | 手工录菜成为瓶颈（每周 > 2 道新菜） | 视频 skill 接真实 API；硬字幕 OCR（G6）；未匹配食材自动出 stub（G1 闭环）；Wikidata 全量种子；界面上的复核队列 | 一条视频到"能教"状态，师傅在界面上确认，Terry 时间 < 20 分钟 |
| 4 | 闭环 | 采购员反映耐放品反复多买；或想看价格变化 | 耐放品 `onHand` 录入；收货回写；计划 vs 实收 | 耐放品连续 4 周不重复采购 |
| 5 | 第二个厨房 | 出现第二个厨房或第二种语言组合 | 语言集可配置；多厨房数据隔离；小程序壳；评分反馈 | 第二个厨房不改代码就能跑 |

**防止再次偏移的五条规则**

1. 每轮只加一个新输出或一个新输入通道。
2. 触发条件必须是厨房里观察到的事，写进 ADR 的第一行。
3. 测试周内 schema 冻结。
4. 黄金测试上锁前，数字必须有人手算一遍并签名（鸡蛋那行的教训）。
5. 每轮最多一篇 ADR；文档行数不得超过代码行数增量。

**风险**

- 单点：Terry 同时是录入者和开发者。第一轮只保留录入这一个人工环节，翻译和分发已经自动；第二轮把录入也交给界面。
- 帮厨流动：备料单的价值恰恰在这里——新帮厨第一天就能看懂。把"新人上手时间"作为长期指标。
- 师傅是否愿意标准化：50 份配方要他拿秤量。这是第一轮最大的不确定性，开工前先问。
