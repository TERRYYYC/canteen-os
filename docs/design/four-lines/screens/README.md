# 四条线设计稿 · v12 图片

> **状态：提案，未签收。** 这些图不是当前版本的页面，也不是验收依据。和现行合同冲突的地方，在图下标了 [上一级 README](../README.md) §4 的条目号，实施前要先改合同。

- **来源**：Terry 在 claude.ai 上的 CanteenOS 设计系统 v12（版本 `1791585029-5922`），共 21 张设计稿，每张中文、English、Українська 并排。
- **怎么导出的**（2026-10-14）：按设计系统的预览框渲染，即 `tokens.json` 编译出的变量加 `components/bundle.css`。用 Chromium 截图：浅色，宽度取每张卡片的宽度（多为 1280），整页高度，1 倍像素，压缩到 256 色。
- **字体**：导出环境没有 Avenir Next 和 PingFang，所以用的是 Inter 和 Noto Sans CJK。在 Mac 上看设计系统，字形会略有不同，排版和文字一样。
- **示例数据**：仓库 `data/` 里有的沿用，包括番茄炒蛋、week-41 的三餐份数、番茄和小葱的包装、人民币价格、供应商；其余是编的。菜盘是插画，不是照片。

## 导航与图片

**0-1 · RoleNav**：底部导航四个入口正好是四条线：备料 · 排菜 · 采购 · 菜品。每个人默认进自己那条线。

![RoleNav](0-1-RoleNav.png)

**0-2 · ImageFrame**：图片的五种状态：加载中、已加载、没有照片（图片还没授权时也这样显示）、加载失败、离线。

![ImageFrame](0-2-ImageFrame.png)

## 1 · 今日备料（帮厨）

**1-1 · TodayPrep**：打开就是今天。按餐次分组，每道菜一行，右边“已备 / 总数”；同一时段要切的合在一起。师傅改了菜，最上面一条黄色提示。

冲突：餐次写了总份数（“160 份”），见 §4 第 1 条。

![TodayPrep](1-1-TodayPrep.png)

**1-2 · DishPrep**：一道菜的备料。先看怎么切，再看要切的食材，最后是调料（备在手边，只写大概用量），做完一项打一个勾。

冲突：给帮厨看原视频片段，见 §4 第 6 条。

![DishPrep](1-2-DishPrep.png)

**1-3 · PrepItem**：同一项，两个人对着看。食材、切法和大小、用于哪道菜、用量四样写全，每样下面一行是对方的语言。

![PrepItem](1-3-PrepItem.png)

**1-4 · AskChef**：不懂就问这一项。先点常用问题，再补一句话、语音或照片；回答挂在这一项上，谁打开都看得到。需要新后端，见上一级 README §6。

![AskChef](1-4-AskChef.png)

**1-5 · CutTerms**：切法叫法表。四个状态（未经实践 / 有疑问 / 试用中 / 已确认），记录来自备料现场，见上一级 README §7。

![CutTerms](1-5-CutTerms.png)

**1-6 · CutSpec**：切法示意图。原片使用权确认之前，用它代替视频片段。

![CutSpec](1-6-CutSpec.png)

## 2 · 一周排菜（师傅）

**2-1 · WeekPlan**：手机上的一周。每天早 / 午 / 晚三张卡，每道菜一行，带不重样提示；先保存，再发布，状态写成人话。

![WeekPlan](2-1-WeekPlan.png)

**2-2 · DishPicker**：选菜面板。标题写“加到 周三 · 晚餐”，默认最久没做的在前，每道菜标“我们的做法”或“原视频的做法”。

冲突：“原视频的做法”可以直接排，见 §4 第 4 条。

![DishPicker](2-2-DishPicker.png)

**2-3 · WeekPlanDesktop**：电脑上的一周。7 天 × 3 餐的格子，右边是菜品库，可以点选或拖进某一餐。

![WeekPlanDesktop](2-3-WeekPlanDesktop.png)

**2-4 · PlanEntry**：排菜里的一行菜：图、菜名和另一种语言、不重样提示（“本周第 2 次”“上次 9 天前”“41 天没做”）、份数（没填写“份数没填”）。

![PlanEntry](2-4-PlanEntry.png)

## 3 · 本周采购（采购）

**3-1 · WeeklyShopping**：按周、按类别。每一类一张卡，写种数和小计、在哪买、“复制这一类”；每行先写下单时要说的箱数。

冲突：以“几箱、多少钱”为主体，见 §4 第 2 条；类别和“在哪买”还没有数据，见 §4 第 3 条。

![WeeklyShopping](3-1-WeeklyShopping.png)

**3-2 · OrderCopy**：复制下单。每行就是下单时说的话；消息语言单独选、按供应商记住，默认只复制没买的、不带价格。当前版本已经有“复制给菜贩”（#140），是这张图的第一步。

![OrderCopy](3-2-OrderCopy.png)

**3-3 · IngredientDetail**：食材详情。包括这周买几箱、上次买了几箱、规格和单价、用在哪几道菜，以及一句人话的换算。

冲突：“上次买了几箱”需要采购历史，见 §4 第 3 条和上一级 README §6。

![IngredientDetail](3-3-IngredientDetail.png)

**3-4 · ShoppingItem**：采购清单的一行。粗体箱数，后面是每箱多少、共多少，右边是金额。

![ShoppingItem](3-4-ShoppingItem.png)

## 4 · 菜品库（师傅，帮厨也能看）

**4-1 · DishLibrary**：像饭馆菜单一样的两列菜卡，三语搜索，按类别和主料筛。每道菜只用三个词说状态：待核对 / 原视频的做法 / 我们的做法。

冲突：三个词要对上来源确认、厨房核定、采用三个动作，见 §4 第 4 条。

![DishLibrary](4-1-DishLibrary.png)

**4-2 · DishPage**：菜品页，像教学 App，同时是我们的菜谱：视频封面 → 食材 → 分步做法 → 来源，最上面一条“我们的做法”。

![DishPage](4-2-DishPage.png)

**4-3 · RecipeChanges**：我们改过的地方。和原视频比，每处一张卡，写为什么、谁、哪天。

![RecipeChanges](4-3-RecipeChanges.png)

**4-4 · AfterService**：做完以后。师傅每道菜点一下（正好 / 太咸 / 剩了很多……），给出具体的改菜谱建议。

冲突：剩菜和份数统计不在本轮范围，见 §4 第 5 条。

![AfterService](4-4-AfterService.png)

**4-5 · DishCard**：菜品库的菜卡：菜名和另一种语言，标签写主料、做法、时长和状态。

![DishCard](4-5-DishCard.png)
