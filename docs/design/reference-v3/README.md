# CanteenOS · Reference v3

根据 2026-09-10 用户提供的绿色九屏参考图制作的交互高保真。九类场景拆为十个画板，采购与报告各占一屏。**设计提案，不替代当前生产页面或已接受的 v2 设计。**

在本目录运行 `python3 -m http.server 4178 --bind 127.0.0.1`，打开 `http://127.0.0.1:4178/`。使用 HTTP 服务器加载 ES modules，不直接双击 HTML。

全部素材和图标已本地化，无需 npm 安装。沿用仓库的原生 DOM、无 UI/CSS 框架约定。

## 可以体验

- 中文 / English / Українська：界面、菜品、食材、烹饪步骤共同切换。
- 首页 → 日/周/月菜单 → 详情 → 点餐意向确认；做法步骤可勾选，星级与标签可提交。
- 知识库按菜品/食材/调料搜索；视频入口可走示例解析、复核与草稿入库。
- 标准文件入口读取 v2 JSON。可使用 [示例文件](fixtures/importable-dish.json)：两份配方、每份鸡肉 200 g、盐适量；引用的是本原型的食材 ID，不能直接当生产数据提交。
- 菜单计划调整每道菜份数；采购单自动汇总、扣减演示库存、计算整包数量；可展开算式、复制和导出 CSV。
- 周/月报告含明确标注的示例指标；新反馈计入本次会话的样本数，厨师/采购反馈与顾客评分分开统计。
- “全部画板”用于团队一起看设计，“交互体验”用于走查主流程。小屏自动切换为全宽应用。

## 边界与接入

本轮全部交互为会话内演示，刷新后恢复初始数据。没有发出真实订单、分析/上传视频、提交线上知识库或写入业务数据库。
导入仅做结构预检，始终落草稿；正式落库还需完整 JSON Schema、引用和资产验证。标准文件的原文、来源和 clip 保存在导入对象的 `sourceDocument` 中，原型仅渲染文字步骤，不播放来源视频。
生成图片用于视觉演示，配方、营养、过敏原与运营指标均不作为经核验的厨房生产数据。营养缺失显示待核算。
业务架构、线上线下导入契约、协作规范与五个开源项目对照见 [PRODUCT-HANDOFF.md](PRODUCT-HANDOFF.md)。

## 验证

运行 `node --test model.test.mjs`：9/9 通过。覆盖手算、加份数、库存覆盖、零需求、缺规格 pending、草稿禁采、三语/步骤保留、适量/包装单位及畸形输入。
中文日计划基准：鸡肉 80 / 时蔬 60 / 汤 60，共 200 菜品份数，金额 ₴6,655。鸡肉加到 90：210 菜品份数，₴7,140。
手算：鸡肉 `16 kg ÷ 0.9 × 1.1 = 19.5556 kg → 10 × 2 kg → ₴3,400`；加到 90 后 `18 ÷ 0.9 × 1.1 = 22 kg → 11 包 → ₴3,740`。
黄油基准 `(2.6 × 1.1 − 0.5) / 0.5 = 4.72 → 5 包 → ₴725`；加份后 `(2.85 × 1.1 − 0.5) / 0.5 = 5.27 → 6 包 → ₴870`。
其余为面包糠 ₴130、西兰花 ₴1,200、胡萝卜 ₴300、番茄 ₴900；油和盐库存覆盖。总增量 `340 + 145 = ₴485`。
浏览器已验证三语切换、菜单加份到采购、逐行 trace、反馈草稿保留/提交、示例导入与草稿搜索、两份配方折算每份；393×852 手机视口与桌面画板有截图。
文件选择器端到端自动化未稳定确认，保留为人工走查项；结构解析有独立单测。乌语仍需母语使用者做实地用词验收。
完整的视觉对照、修正记录及测试覆盖边界见 [design-qa.md](design-qa.md)。
