CanteenOS · 师傅后台 · v1

后台七个屏幕：排菜单、导入、加菜、复核、食材、发布

给不写代码的人：师傅、采购员。原则是每屏只做一件事，字段能省则省，能自动填的自动填（翻译、食材名、份数换算），错误当场标黄而不是拒绝。不追求好看，追求一只手能操作。全部中文，因为这些人是中国人。

入口与排菜单

/admin · /admin/plan

师傅从同一个目录角标进后台。工作台只有六个大块；排菜单是按天的列表，不是七列网格——手机竖屏一列更好按。份数用 ±10 的步进器，旁边给上周实际数。

后台怎么写数据，又不需要账号、不自建后端

前台三张单是纯静态页面，这一点不变。后台要写，最省的路是：后台页面也是静态的，写操作发给一个很小的云函数，它拿仓库的 token 把 JSON 提交进 git，然后自动构建上线。师傅不需要 GitHub 账号——他拿到的是一个带钥匙的链接，扫码或收藏即可。

师傅手机（后台 PWA）
  │  改份数 / 建食材 / 贴视频链接 / 按发布
  ▼
云函数（一个文件，Cloudflare Worker 或同类）
  │  校验 → 写 data/*.json → git commit → 触发构建
  │  视频链接 → 触发 skill（GitHub Action，带 GEMINI_API_KEY）→ 产出草稿进"待确认"
  ▼
仓库 data/ ──构建──▶ 静态站：/prep /purchase /menu /admin
                       └ 帮厨、采购员、顾客扫码打开

钥匙就是链接里的一串随机字符，一个角色一条链接，泄露了就换一条。第一轮够用；第二个厨房或第二个师傅出现时再考虑真正的登录。

这条路和 roadmap-v2 的差别：原来"写入上屏"排在第二轮，现在第一轮就要有排菜单和发布这两个屏，因为师傅不能靠别人改 JSON。视频导入和复核屏可以第二轮再上——命令行版的 skill 已经能跑，第一轮的新菜可以先由 Terry 用命令行导入，师傅在复核屏看。
